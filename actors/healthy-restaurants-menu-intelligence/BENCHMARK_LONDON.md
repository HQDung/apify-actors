# London benchmark

Phase 5 dietary, published-nutrition, and healthy-positioning enrichment is implemented. A Phase 5 run discovers Google Maps places, crawls bounded official homepages, fetches supported HTML menu candidates, records deterministic menu items with provenance, and classifies positioning only from explainable official evidence. PDF/image parsing, estimated nutrition, allergen guarantees, and third-party content remain excluded.

The benchmark uses the documented [Phase 2 sample input](./sample-input-phase2.json) with `includeMenu: false` for discovery-only runs; the [sample-input-phase5.json](./sample-input-phase5.json) input with `includeMenu: true` exercises Phase 5 enrichment as well.

Phase 5 regression coverage: 158 tests pass and 1 is skipped locally (including deterministic legend, dietary provenance, published nutrition, classification, and menu-page enrichment cases). The final local Phase 5 smoke run (2026-07-28) discovered 30 Google Maps cards, retained 10 restaurants after deduplication, found 10 websites, attempted 6 HTML menu pages, extracted 0 items, and exited successfully with 10 schema-valid records. Menu statuses were `website_unreachable: 6`, `menu_not_found: 2`, and `extraction_failed: 2`; 2 records contained restaurant-level dietary options, while item-level dietary and published-nutrition coverage was unavailable because of live page failures. Runtime was 72.28 seconds versus 59.30 seconds for the Phase 4 comparison run (+21.85%); output was 22,197 bytes. Deterministic fixtures cover the positive extraction paths.

## Phase 6 reliability benchmark (2026-07-29)

Phase 6 uses the exact [small benchmark input](./validation/phase-6/small-benchmark-input.json) and [standard benchmark input](./validation/phase-6/standard-benchmark-input.json). Both final local runs exited successfully and pushed only schema-valid records. The small run discovered 10 raw places and retained 10 restaurants in 54.46 seconds; it reached 4 websites, processed 9 HTML menus, and extracted no items because of live page failures. The standard run discovered 120 raw places across four search jobs, retained 30 restaurants in 255.19 seconds, reached 13 websites, processed 31 HTML menus, and retained 117 deduplicated items across 3 extracted restaurant menus. The standard run pushed 30/30 valid records after fixing an undefined internal duplicate-item evidence field. Local compute cost was not exposed. The pushed private cloud Actor build `0.1.1` was then tested with menu enabled, menu disabled, and three keywords: all 3 runs succeeded, produced 40/40 schema-valid records with 0 duplicate IDs, ran for 326.034 seconds total, used 0.362260 compute units, and reported $0.074536 total usage. Cloud menu-enabled samples produced no menu items or published nutrition values because of live source-page failures; the menu-disabled run emitted 10/10 `not_requested` records. Full counters and limitations are in [validation/phase-6/local-benchmark-results.json](./validation/phase-6/local-benchmark-results.json), [cloud-benchmark-results.json](./validation/phase-6/cloud-benchmark-results.json), and [publish-readiness-report.md](./validation/phase-6/publish-readiness-report.md).

The timeout remediation deduplicates place cards and caps Google Maps detail extraction at `maxRestaurants` before website/menu enrichment. Build `0.1.2` passed the exact default five-keyword cloud test in 202.394 seconds with 30/30 schema-valid records, 0 duplicate IDs, 78 menu items, and $0.046289 reported usage.
